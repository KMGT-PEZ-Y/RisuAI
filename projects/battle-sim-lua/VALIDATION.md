## 재현

프로젝트 폴더를 기준으로 실행합니다. Python 테스트에는 Lua 5.4를 포함한 `lupa`가 필요합니다. 이번 환경에서는 개발 의존성을 `.qa-deps`에 설치했습니다. Wasmoon은 `.qa-web/node_modules`, Playwright는 Codex 제공 패키지를 사용했습니다. 의존성·화면 캡처·중간 결과는 CHARX에 포함되지 않습니다.

```powershell
python build.py
python qa.py
node qa_wasmoon.mjs
node qa_browser.mjs
node validate-lua-structure.mjs BattleSim.lua
```

WASM 검증은 `qa-output/risu-json.lua`에 RisuAI 공식 `public/lua/json.lua`를 준비해야 합니다. Python 테스트가 HTML 샘플을 만들므로 브라우저 검사 전에 실행합니다. 테스트 결과는 `qa-output/results.json`, `qa-output/wasmoon-results.json`에 기록됩니다.

## 확인한 한계

- 설치된 **RisuAI.exe에서 직접 CHARX를 가져오는 작업은 수행하지 않았습니다**. 같은 런타임 계열과 공식 JSON/Promise 계약, 독립 브라우저에서 검증한 결과입니다. 설치본의 버전별 HTML 처리 차이까지 검증했다는 뜻은 아닙니다.
- 사진은 사용자가 추후 추가하기로 한 상태입니다. 실제 캐릭터·스킬 사진의 구도와 겹침은 제공된 사진이 없으므로 검증하지 않았습니다. 파일명과 비율은 `ASSETS.md`에 정리했습니다.
- Python MT19937과 Lua LCG의 난수열은 다릅니다. 동일 숫자 시드의 경기 전체 일치 대신 **동일 행동·주사위 시나리오의 결과 일치**를 검증했습니다.
- 적 정보 제한은 화면 표시 정책입니다. NG+는 Python POC와 같이 전투 상태 모델을 사용하며, 이번에 제출 중인 플레이어 선택과 실제 전투 RNG는 읽지 않습니다. 로컬 저장 자체를 암호화하거나 사용자의 개발자 도구 접근을 막지는 않습니다.
- RisuAI 실행기의 mutex 때문에 탐색 도중 별도 취소 버튼이 즉시 처리된다고 보장할 수 없어 취소 UI를 추가하지 않았습니다. 탐색은 최대 전이 횟수로 제한하고 128회마다 비동기 양보합니다.

실행기 API 계약은 [RisuAI 공식 Lua 문서](https://kwaroran.github.io/docs/srp/lua/)와 [공식 실행기 소스](https://github.com/kwaroran/RisuAI/blob/main/src/ts/process/scriptings.ts)를 기준으로 확인했습니다.
