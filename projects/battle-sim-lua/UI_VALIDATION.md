# Battle Sim UI 구현·검증 — 2026-09-08

## 최신 보완: 동일 이미지 재등장 제거

`B.mergePortraitStages()`가 인접한 동일 에셋 경로를 하나의 연출 구간으로 합친다. 예를 들어 action / resolve / reaction / reaction / reaction은 세 개의 이미지 요소로 렌더링되며 마지막 이미지는 3~5단계를 연속 유지한다. A/B/A처럼 사이에 다른 이미지가 있는 경우는 세 구간을 그대로 유지한다.

구간에는 시작 단계의 등장 효과와 마지막 단계의 퇴장 효과만 적용한다. 시작 이미지가 이전 초상화와 같으면 등장/이전 초상화 퇴장을 생략한다. 마지막 이미지가 복귀 초상화와 같으면 끝까지 유지하고 5.5초에 같은 모양의 스탠딩으로 즉시 인계한다. 이 인계에는 fade/pop이나 두 레이어의 동시 표시가 없다. 기존 주사위 시점·전체 연출 5.5초·Continue·박동·저장 형식은 유지한다.

검증 결과:

- 일반, 다운, KO, 인터벌, 기상, 다운 대기, 그로기, 양측 그로기, 빠른 진행: **99,036지점**에서 스탠딩/연출 중첩 없음.
- 유지 구간 **68,820지점**에서 opacity=1, scale=1, translate=0 및 가시 상태 확인. 단계 경계에서 재등장/깜빡임 없음.
- 일반 reaction은 3~5단계 단일 요소, 다운 대기는 시작/끝 초상화까지 하나의 유지 구간으로 연결됨을 확인. 이미지가 바뀌는 구간의 부드러운 등장/퇴장은 유지.
- 수정 직전 백업의 Lua와 **58레벨·1,813턴** 저장 필드 일치. NG+ 12턴/JSON 왕복/중복 실행 검사, 기존 스킬 UI/주사위/박동/5개 해상도 검사도 통과. Lua/브라우저 오류 0.
- 백업: `BattleSim-RisuAI.before-deduplicated-transitions.charx`, 39,925 bytes, SHA256 `d25cd85b01aec6b3388e314eefc677e65991bfdca4bf2c28a7ed1f780165050d`. 백업을 수정하지 않고 새 패키지의 입력으로 사용했으며, 카드/모듈 이외의 기존 ZIP 항목도 바이트 일치를 확인했다.

백업 Lua를 추출한 경로를 `node qa_regression.mjs <Lua 파일 경로>`로 전달하면 직전 버전과의 비교를 재현할 수 있다. 아래 기록은 앞선 구현/보완 내역이며, 고정 5단계별 pop-in/out 대신 위의 구간 병합이 최신 동작이다.

## 추가 요청 반영: 연출 복원과 스킬 UI

- 각 초상화 안에 둥근 주사위 굴림을 복원했다. 0.24초부터 회전/튕김 및 임시 눈 변화가 진행되고, 1.6초에 `presentation.playerDie/enemyDie`의 실제 눈과 판정 결과가 공개된다. 빠른 진행/동작 줄이기에서는 실제 눈을 즉시 표시한다.
- 5개 연출 구간에 연속적인 opacity, scale, translate 보간을 추가했다. 이미지가 부드럽게 pop-in/pop-out하며 기존 5.5초 순서와 스탠딩 비중첩 구간을 유지한다.
- 양측 스탠딩 박동은 HP >60%에서 3.6초/1.007배, >35%에서 2.6초/1.015배, >15%에서 1.7초/1.028배, 그 이하에서 1초/1.045배다. 다운/그로기는 HP보다 우선하여 4초/1.016배로 박동한다. KO/경기 종료에는 움직이지 않고 동작 줄이기에서는 박동을 끈다. 이는 표시 효과 값으로 전투 규칙을 변경하지 않는다.
- HP/STA/BRK 변화 팝업에 45% 불투명도의 검정 배경, 얇은 검정 테두리, 8px 둥근 모서리와 부드러운 등장 효과를 적용했다.
- 스킬 사진을 켜면 양측 장착 스킬 버튼이 기존 raw 에셋 경로의 이미지로 표시된다. 접근 가능한 이름, 키보드 포커스, 설명 팝오버를 유지한다. 설정에서 바꾼 사진 모드는 현재 경기에도 반영한다.
- 이번 턴 스킬은 이름/상태를 두 열로 배치한 단일 버튼이다. 상태 영역을 눌러도 선택된다. 실행 불가 시 버튼이 비활성화되고 문구가 실제 불가 사유(예: 행동 조건 불일치)로 바뀐다. 버튼 아래의 별도 사유 문구는 제거했다.

추가 검증: 주사위 굴림/눈 변화/최종 6:1, 5단계 pop-in/pop-out의 중간 불투명도, 양측 6개 체력·상태별 박동 주기/최대 배율, 변화 팝업 테두리·투명도, 이미지 모드 10개 버튼/오버레이, 통합 카드의 내부 경계/클릭, 실행 불가 버튼, 빠른 진행/동작 줄이기를 검사했다. 기존 5개 데스크톱 해상도 검사에 이미지 모드 + 긴 로그/상태/알림을 추가했다. 스탠딩 비중첩 88,032지점 검사도 통과했다.

늘어난 반복 렌더 검사에서 Wasmoon 1.16의 반환값이 전역 C API 스택에 남는 테스트 하네스 문제를 발견했다. `qa_ui.mjs`의 각 호출 후 스택을 원래 높이로 돌려놓도록 수정했으며 재실행에서 오류가 없었다. 배포 모듈/전투 엔진은 이 개발용 하네스에 의존하지 않는다.

- `src/presentation.lua`: 기존 에셋/판정 헬퍼를 사용한다. `B.ruleRows()`는 전투와 AI가 쓰는 `src/legacy.lua`의 `RESULT_TABLE` 27항목과 `GROGGY_TABLE` 3항목을 직접 참조한다. 수치 복제나 전투 계산 변경은 없다.
- `src/battle.css`, `src/skills.css`: 가로 대치, 하단 정렬 상태 바, 검정/빨강 및 제한적인 금색, 직사각형 버튼과 포커스 표시. 데스크톱은 남은 화면 높이에 따라 초상화가 줄어든다. 공간이 충분하면 약 16:10이며 짧은 화면에서는 가로 비율이 더 커진다. 적 이미지에만 좌우 반전을 적용한다.
- `assemble.py`: 옛 초상화/연출 마크업을 배포 코드에서 제외하고 새 표시 소스와 CSS를 조립한다. `BattleSim.lua`, `BattleSim.css`, `BattleSim-RisuAI.charx`를 재생성했다.
- 저장 키, 상태 버전, 저장 필드, 엔진/AI/스킬 정의는 변경하지 않았다. NG+가 양보 중일 때 다른 버튼 이벤트가 진행 상태를 덮어쓰지 않도록 기존 busy 잠금을 적용했다.

## 연출과 팝오버

모든 이미지가 기존 `presentation.sequenceId`의 단일 5.5초 CSS 타임라인을 사용한다. 약 0–0.24초 이전 초상화 fade-out → 행동 → 판정 → 효과 → 상태/기상 → 다운/KO/결과 → 5.2초 이후 최종 초상화 fade-in 순이다. 스탠딩과 연출의 가시 구간은 분리되어 있다. 완료된 연출 이미지는 `visibility:hidden; opacity:0`이며 Continue는 완료 전 키보드 포커스 대상에서도 제외된다. 빠른 진행/동작 줄이기는 중간 레이어를 전부 숨기고 최종 초상화로 즉시 이동한다.

이전 초상화는 기존 저장된 자원 차이와 진입/기상 플래그로 복원한다. 라운드 종료 시 기존 `displayActors`와 `pendingInterval`을 그대로 사용한다. 중복 이벤트는 기존 match/turn/sequence 토큰과 busy 잠금을 따른다.

스킬은 실제 `button` + `popover="auto"` / `popovertarget` / `aria-controls`를 사용한다. **aria-expanded는 네이티브 invoker의 암시적 접근성 상태**로 제공되며, 정적인 false 속성으로 덮어쓰지 않는다. Chromium 접근성 트리에서 열기 전 false, 열린 뒤 true, 닫힌 뒤 false를 직접 검사했다. Lua 스킬 정의만으로 설명을 만들며 현재 자원/CD/사용 횟수는 넣지 않는다.

판정 화면도 네이티브 팝오버로 모듈 위를 덮고 뒤의 전투 UI를 숨긴다. 브라우저 페이지 이동, Lua 호출, DOM 교체, 전투 저장, 애니메이션 재시작이 발생하지 않는다. 표만 내부 스크롤하며 제목/복귀 버튼은 그대로 보인다. 팝오버는 RisuAI의 스크립트 제거 환경에서도 동작하며 외부 JS/프레임워크가 필요 없다.

## 확인 범위의 한계

설치된 RisuAI 앱에 CHARX를 직접 가져오는 시험은 하지 않았다. 앱의 전체 채팅 UI 크롬/사용자 CSS는 검증 호스트에 포함되지 않는다. 팝오버 지원 Chromium/WebView2가 필요하다. 브라우저 검사는 사용자 에셋을 변경하지 않는 대체 이미지로 레이어 동작을 검증했다. 배포본의 `{{raw::접두사_파일.png}}` 규약은 유지되며 실제 에셋 등록 상태/디코딩 지연은 사용자 앱에서 확인해야 한다.

기존 Python ↔ Lua `qa.py` 전체 검사는 이 환경의 Lupa를 사용할 수 없어 이번에 다시 실행하지 않았다. 이전 검증 기록은 `VALIDATION.md`에 날짜를 구분해 보존했으며, 이번 변경은 Wasmoon에서 수정 전 Lua와 직접 대조했다.

- 이미지 여백 방어: 브라우저에 `img{margin-top:20px}`를 추가한 상태에서 초상화·연출·스킬 이미지의 computed margin-top이 모두 0px임을 확인. 5개 화면 크기와 기존 연출 검사 통과. 실제 호스트에서 20px을 주는 원본 스타일은 로컬 소스에서 확인하지 못했으며, 재현 조건을 주입해 검증함.
