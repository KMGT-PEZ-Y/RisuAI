# NG+ 공용 스킬 AI · Python POC

2026-09-04 구현. M/U/H 구분 없이 장착한 스킬에서 기본 행동과 스킬을 함께 선택한다. 고정 덱이나 스킬 ID별 사용 일정이 없다. 전투 규칙은 기존 `BattleEngine`을 그대로 가상 실행한다.

## 사용

1. `play_ng_plus.cmd` 또는 `play_muh_skills.cmd` 실행.
2. Enemy AI에서 `NG+ · 행동+스킬 통합 · 3턴 탐색` 선택(기본값).
3. 양측 목록에서 Ctrl/Shift로 스킬을 각각 0~5개 선택.
4. 판단 충실도 0~1을 지정하고 `선택한 장착으로 새 경기` 클릭.
5. Player의 행동·스킬을 선택해 턴 실행. `NG+ 판단` 탭에서 후보 점수와 예상 연계를 확인.

장착·AI·판단 충실도 변경은 새 경기부터 적용된다. 기존 제어/결정기 각각 1개 및 H08+H09 동시 장착 금지 규칙은 유지한다. 계산은 별도 스레드에서 실행하며 새 경기 또는 창 종료 시 취소한다. Enemy 수동 입력은 NG+ 선택 중 비활성화된다. 기존 행동 AI를 선택하면 수동/무작위 스킬/무스킬 모드도 사용할 수 있다.

판단 충실도는 조절할 게임 파라미터 하나다. 1이면 평가 점수에 따른 선택만, 0이면 합법적인 행동+스킬 후보 중 균등 무작위다. 중간값 q는 q 확률로 평가 기반, 1-q 확률로 균등 선택한다. 평가 기반 선택도 온도 2의 softmax를 사용하므로 비슷한 점수끼리는 다양성이 있다. q=0은 탐색을 생략한다. q를 올린다고 개별 경기 승률이 반드시 단조 증가하는 것은 아니다.

## 판단 과정

1. 공개 상태, 양측 장착·HP/STA/BRK·CD·남은 횟수·상태이상과 완료된 행동 기록을 복제한다. 현재 Player 입력과 실제 전투 RNG는 읽지 않는다.
2. 기본 행동 3개와 각 행동에 붙일 합법 스킬/미사용을 열거한다. 최대 5슬롯이므로 한쪽 후보 A는 최대 18개다.
3. K개의 가상 상대 행동·주사위 흐름을 만들고 모든 후보에 같은 난수 흐름을 적용한다. 상대는 최근 8회 공개 행동의 감쇠 빈도와 스킬 사용 비율로 추정하며 모든 합법 선택에 양의 확률을 남긴다.
4. 현재 선택별로 최대 3턴을 탐색한다. 2턴까지 확장한 뒤 상위 B개 후속 경로를 유지하고 3턴을 확장한다. 준비 상태를 남긴 경로 하나를 보존하여 즉시 피해만 좋은 후보에 연계가 모두 밀리지 않도록 한다.
5. 상위 F=4개 현재 선택에 대해 첫 턴의 상대 선택과 주사위 기대값을 다시 계산한다. 주사위 수치 효과가 없으면 승/무/패 확률 15/36·6/36·15/36으로 정확히 합산하며, 수치 의존 효과가 있으면 36쌍을 전부 실행한다. 이는 추정한 상대 행동 분포 안에서의 정확한 첫 턴 기대값이다.
6. 보정 점수 = 표본 기반 3턴 점수 − 표본 기반 첫 턴 점수 + 정확한 첫 턴 기대값. 후속 두 턴은 여전히 표본 추정이다. 보정한 최종 후보에서 판단 충실도에 따라 선택한다.

같은 미래 행동열을 여러 시나리오에서 비교하는 방식이다. 미래에 계획한 스킬이 불가능해지면 같은 기본 행동의 무스킬로, 그 행동도 금지되면 합법 기본 행동으로 대체한다. 실제 경기에서는 매 턴 처음부터 다시 판단한다. 전체 최적해나 모든 상대 전략에 대한 승리를 보장하는 탐색은 아니다.

평가에는 남은 다운 여유를 포함한 유효 HP, STA, BRK 누적 위험, 그로기·다운 대기, 스킬 잔여 횟수/CD와 탐색 밖에 남는 상태 효과의 작은 추정값을 사용한다. 준비·할인·제어·주사위 변경의 탐색 내 효과는 실제 실행기가 계산한다. KO는 ±1000, 동시 KO는 0이다. 같은 평가값으로 마무리 가능한 무스킬 후보가 있으면 평가 기반 선택에서 스킬 낭비 후보를 제외한다. 표시 점수는 승률이 아니다.

## 계산량과 기본값

현재 기본값은 **깊이 D=3, K=4, B=2, F=4**다. 앞서 설계에서 제안한 K=8/B=4는 `REFERENCE_CONFIG`로 남겼다. K=8이 필수적인 정확도 기준은 아니며, Python POC의 응답 시간을 확인한 뒤 기본 계산량을 낮췄다. 동일한 초기 사례에서 K4/B2 약 117ms, K8/B4 약 349ms가 측정되었다. 깊이는 모두 3이다.

가상 턴 실행 횟수의 상한(D≥2):

`K × [A + A² + (D−2) × B × A²] + F × Ao × 36`

- A: 자기 후보 수 ≤18, Ao: 상대 후보 수 ≤18.
- 기본값 상한 **6,552회**, 참고 설정 상한 **15,696회**. 실제 가능한 후보만 열거하므로 보통 이보다 작다.
- 별도 하드 예산으로 가상 턴 횟수를 제한한다. 예산이 부족하면 모든 현재 후보에 대해 끝낸 마지막 깊이 결과를 사용한다. 일부 후보만 보정한 결과도 사용하지 않는다.
- 한 번의 상태 복제·규칙 실행·평가 비용을 C라 하면 주요 시간 복잡도는 위 실행 횟수에 C를 곱한 값이다. 경로 정렬의 추가 비용은 `O((D−1) × A × BA × log(BA))`다. 스킬·상태 목록을 무제한 늘리면 C도 증가한다.
- 복제된 상태 하나의 크기를 S라 하면 메모리는 **O(K × A × B × S)**다. 현재 선택마다 후보를 유지하고 일시 확장 배열도 만들기 때문에 단일 beam의 메모리만으로 계산하지 않는다.

Lua 이식 시에도 깊이 3, 고정 후보/시나리오/예산 상한을 유지할 수 있다. 다만 Lua 런타임의 실행 시간은 아직 측정하지 않았다. Python 객체 복제를 그대로 번역하기보다 작은 상태 테이블과 버퍼를 재사용하는 것이 후속 이식 과제다.

## 검증과 한계

- 자동 테스트 총 **149개 통과**(기존 133 + NG+ 16).
- 30종 각각의 가상 실행과 실제 실행 상태 일치, 라운드 경계·대기·준비 만료, 정보 비노출·RNG 보존·재현성, 탐색/취소/예산, 제어 준수, H05→H06 계획 검증.
- `qa_ng_plus_ui.py`: 실제 Tkinter 숨김 창에서 자유 장착, 비동기 턴, 판단 로그, 새 경기 취소, 빈 덱, q=0, 기존 수동 모드 확인.
- `qa_ng_plus_matches.py`: 시드 20260904~20260906, 서로 다른 동일 장착 3경기. Player는 합법 행동+스킬 후보 균등 무작위, Enemy는 NG+ q=1. 각 45/40/29턴 종료, Enemy 2승·Player 1승.
- 이 3경기의 98회 판단: 중앙값 **94.29ms**, P95 **156.58ms**, 최대 **221.84ms**, 최대 가상 턴 **1,094회**. 현재 Windows/Python 환경의 소규모 안정성 표본이며 속도 보장·NG+ 난이도 확정·덱 밸런스 검증이 아니다.

후속 과제는 다양한 덱/상대/시드에서 판단 충실도별 성능, 할인 준비의 사용 가치, 제어/회복 중심 덱의 효용을 검증하고 Lua에 이식하는 것이다.

## 코드 연결

- `ng_plus_ai.py`: 공개 상태 스냅샷, 공통 평가·탐색, 결정 요약.
