# 쉬움 적 액티브 스킬과 선택 규칙

2026-09-03 구현. 수치는 합의한 **1레벨 플레이테스트 초안**이며 밸런스 확정값이 아니다.
기존 기본 행동 AI와 Phase A-D 효과 실행기는 유지한다. 선택기만 되돌려도 이 문서의 스킬 데이터와 수동 사용은 보존할 수 있다.

## 합의한 설계 기조 8항

1. 쉬움은 3개, 보통·어려움은 4개, 매우 어려움은 5개의 액티브 스킬을 가진다.
2. 쉬운 적은 단순하고 서로 직접적인 연계 시너지가 없는 스킬을 사용한다.
3. 난이도가 올라갈수록 연계 시너지와 발동 구조의 복잡성이 커진다.
4. 고난도 적은 높은 가치와 큰 비용을 가진 스킬을 하나씩 보유한다.
5. 쉬운 적의 스킬은 공격 강화·회복·방어 보조처럼 역할을 명확하게 나눈다.
6. 보유 개수와 사용 빈도를 분리하며, 쉬운 적의 스킬 사이에 기본 행동 구간을 둔다.
7. 개별 설명은 간단하게 유지하고, 복잡성은 관찰하고 대응할 수 있는 연계에서 만든다.
8. 고위력·고비용 스킬에는 실제 제약과 공략 가능한 준비·사용 후 빈틈이 있어야 한다.

## 구현한 스킬

각 적은 아래에서 정한 3개를 장착한다. 공유 스킬을 합치면 총 5종이다.

| ID | 이름 | 허용 기본 행동 | 이번 턴 효과 | 효과 발동 조건 |
|---|---|---|---|---|
| `rookie_power_strike` | 힘주어 치기 | 공격 | 상대 HP 피해 ×1.2 | 상대 HP 결과 변화량 < 0 |
| `rookie_recovery_form` | 자세 정비 | 방어 | 자기 HP 회복 ×1.5 | 자기 HP 결과 변화량 > 0 |
| `rookie_safe_footwork` | 안전한 발놀림 | 회피 | 자기 HP 피해 ×0.8 | 자기 HP 결과 변화량 < 0 |
| `rookie_create_distance` | 거리 확보 | 회피 | 자기 BRK 증가량 ×0.8 | 자기 BRK 결과 변화량 > 0 |
| `rookie_tuck_chin` | 턱 당기기 | 공격 | 자기 HP 피해 ×0.8 | 자기 HP 결과 변화량 < 0 |

모두 기존 `result_modifier/multiply`를 `before_result_apply`에 적용한다. 발동 조건은 `application.condition`이며 선택 가능 조건이 아니다. 결과를 미리 알아야 선택할 수 있는 스킬이 아니다.

| 공통 설정 | 의미·단위·적용 범위 | 현재값 |
|---|---|---|
| 레벨 | 이번 테스트에 구현·장착한 스킬 레벨 | 1 (상위 레벨 미설계) |
| 비용 | 시전 확정 시 자기 STA에서 차감, 결과 적용 전 지불 | 8 STA |
| 최소 잔량 | 비용 지불 후 허용하는 최소 STA | 0 STA |
| 개별 쿨다운 | 스킬 자체의 재사용 제한 | 0턴 |
| 사용 횟수 | 경기·라운드별 스킬 사용 제한 | 모두 없음 |
| 지속 | 해당 턴의 결과표 변화량만 수정 | 즉시 효과, 상태·예약 없음 |
| 효과 우선순위 | 기존 실행기에서 application 처리 순서를 정함; 선택 우선순위가 아님 | 100 |

계산은 기존 스키마처럼 **부호가 있는 변화량에 곱한 뒤 내림**한다. 예: 피해 -36의 20% 감소는 `floor(-36 × 0.8) = -29`, 피해 -28의 20% 증가는 -34다. 자원 최댓값 제한도 기존 실행기에서 적용한다.

## 적별 행동과 선택 일정

순번은 `len(action_history[actor]) + 1`이다. 경기 전체의 자기 행동 횟수이며 라운드마다 초기화하지 않는다.

| 자기 행동 순번 (6회 반복) | rookie_cycle | reckless_raider |
|---|---|---|
| 1 | 공격 + 힘주어 치기 | 공격만 |
| 2 | 방어만 | 공격 + 힘주어 치기 |
| 3 | 회피 + 안전한 발놀림 | 방어만 |
| 4 | 공격만 | 공격 + 턱 당기기 |
| 5 | 방어 + 자세 정비 | 공격만 |
| 6 | 회피만 | 방어 + 자세 정비 |

`rookie_guard`는 기존 방어 45%·공격 30%·회피 25%를 유지한다. 자기 행동 3·6·9…번째에 이미 선택된 행동에 따라 방어→자세 정비, 공격→힘주어 치기, 회피→거리 확보를 사용한다. 나머지 두 행동에는 스킬을 쓰지 않는다.

`reckless_raider`의 자기 BRK 80 이상 방어 예외가 우선한다. 공격 스킬 예정 위치에서 방어로 바뀌면 해당 스킬을 생략하고 순서는 진행한다. 자세 정비로 대체하지 않는다. 스킬 효과로 상태가 달라져 다음 기본 행동 분기가 달라질 수는 있다.

공통 실패·정지 계약:

- 예정 스킬을 기존 `validate_intent`로 검사한다. 장착 없음·행동 불일치·STA 부족·쿨다운·횟수 제한은 생략 사유다.
- 생략해도 기본 행동과 순서를 유지한다. 다른 스킬 선택·재추첨·다음 턴 이월은 없다.
- 시전 확정 후 개별 효과 조건이 실패하면 비용을 돌려주지 않는다. HP가 가득 찼거나 피해가 없을 것으로 예상된다고 일정을 바꾸지 않는다.
- 자기 그로기와 양측 중 하나의 다운 대기에는 자기 행동 순번이 진행하지 않는다. 상대만 그로기여서 자신이 행동하면 진행한다.
- 모든 새 스킬은 즉시 효과라 서로 다음 턴 강화나 비용 공급을 만들지 않는다.

## 랜덤 Player 비교 조건

Player는 상대와 **동일한 3개 스킬·동일한 1레벨**을 장착한다.
기본 행동은 각 1/3, 스킬은 선택된 행동에서 현재 사용 가능한 장착 스킬과 미사용을 합쳐 균등 선택한다.
따라서 사용 가능한 스킬이 1개면 시전 확률은 1/2, 2개면 2/3이다. 무조건 시전하거나 효과를 보고 고르는 정책이 아니다.
특히 돌격병과 같은 장착의 Player는 회피 전용 스킬이 없으므로 회피할 때 스킬을 쓰지 않는다.

`run_easy_enemy_simulation.py`가 적별 1,000회, 총 3,000회를 실행한다. 시드와 양측 장착, 스킬 원본 데이터, 일정, 승패·턴·사용 횟수·미사용 사유는 JSON에 기록한다. 현재 결과는 `EASY_ENEMY_PLAYTEST_RESULTS.md`를 참조한다.

## 구현 경계와 검증

- `easy_enemy_skills.py`: 스킬 콘텐츠. `easy_enemy_profiles.py`: 장착·일정 콘텐츠.
- `skill_selection.py`: 확정된 기본 행동에 스킬만 추가. 상대 상태나 현재 선택을 전달받지 않으며 효과를 실행하지 않는다.
- `BattleEngine`의 `player_skill_policy`·`enemy_skill_policy`는 기본값 `none`. 기존 호출과 기존 C-D 테스트베드는 자동 스킬을 사용하지 않는다.
- 랜덤 스킬 난수는 각 진영의 행동 난수와 전투 주사위에서 분리한다. 예정형 적은 스킬 난수를 소비하지 않는다.
- `preview_skill_decision`은 주어진 행동에 대해 복제한 난수 상태로 조회하며 실제 선택·자원·로그·순번을 변경하지 않는다. UI는 선택 결과 로그를 읽으며 상대 행동을 미리 뽑지 않는다.
- `skill_selection` 트레이스에 기본 행동, 자기 행동 순번, 예정·선택 스킬, 생략 사유를 기록한다.
- 새 계약 테스트 20개와 기존 86개, 총 106개 통과. 새 스킬은 양측 각각에서 모든 상대 행동·주사위 승패 조합으로 검증했다.
- 무스킬 결과 동등성, 기존 기본 행동과 난수 소비 보존, BRK 예외, 시전 실패, 라운드 경계, 다운·그로기 순번, 현재 상대 선택 비공개, 조회 무부작용을 확인했다.

## 직접 플레이

`play_easy_enemies.cmd`를 실행한다. Enemy 3종 중 하나를 고르고 Player는 새 5종 중 최대 3개를 장착할 수 있다.
`적과 같은 장착으로 새 경기` 버튼은 선택한 Enemy와 같은 세트를 바로 장착한다. 기본 행동·스킬을 고른 뒤 `턴 실행`으로 진행한다.
양측 장착·자원, Enemy 규칙과 다음 자기 행동 순번, 선택·생략 이유, 효과 전후 값, 결과표를 확인할 수 있다.

기존 `play_skill_testbed.cmd`의 14종 C-D 예제와 무스킬 Enemy 시험은 별도로 유지한다. 보통 이상 적의 스킬, 성장 레벨 수치, Lua 동기화는 이번 구현 범위가 아니다.
