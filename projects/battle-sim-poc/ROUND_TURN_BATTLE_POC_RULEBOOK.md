# 라운드-턴제 배틀 시뮬레이터 POC 룰북

- 문서 버전: 0.6
- 작성일: 2026-08-29
- 상태: 1 대 1 무스킬 코어 구현 완료, 스킬·상태이상 실효·다인 교대는 확장 명세
- 적용 범위: 현재 구현은 1 대 1, 목표 명세는 1 대 N/N 대 N 교대전까지 포함

## 1. 문서 목적

이 문서는 복싱·킥복싱·MMA의 공방을 모티프로 한 라운드-턴제 배틀 시뮬레이터의 POC 구현 기준을 정의한다.

본 문서의 목적은 다음과 같다.

1. 동일한 입력과 난수 시드가 항상 동일한 전투 결과를 만들게 한다.
2. 행동 판정, 자원 변화, 상태이상, 다운, 라운드 교대의 처리 순서를 고정한다.
3. 27개 기본 결과표와 스킬을 코드가 아닌 데이터로 교체·조정할 수 있게 한다.
4. 아직 확정되지 않은 규칙을 구현자가 임의로 해석하지 않도록 분리한다.

## 2. 용어

| 용어 | 정의 |
|---|---|
| 경기(Match) | 어느 한 진영이 패배할 때까지 이어지는 전체 전투 |
| 라운드(Round) | 8번의 턴 시행으로 구성되는 단위 |
| 턴 시행(Exchange) | 양측의 선택, 주사위 판정, 결과 적용이 한 번 완료되는 단위 |
| 활성 캐릭터 | 현재 라운드에 실제로 출전 중인 캐릭터 |
| 벤치 캐릭터 | 팀에 속해 있으나 현재 라운드에는 출전하지 않은 캐릭터 |
| 다운(Down) | HP가 0이 되어 일시적으로 전투 불능이 된 상태 |
| KO | 다운 카운트가 최대 다운 카운트에 도달하여 경기에서 영구 탈락한 상태 |
| 완전 그로기 | 브레이크 게이지가 최대치에 도달하여 행동할 수 없는 상태 |
| 예약 효과 | 캐릭터 객체에 귀속되며 남은 턴 수를 갖는 상태이상 또는 지연 효과 |

문서에서 별도 언급이 없는 한 `턴`은 `턴 시행`을 뜻한다.

## 3. 기준 캐릭터

POC의 정규화된 기준 캐릭터는 다음 능력치를 사용한다.

| 능력치 | 기준값 |
|---|---:|
| 최대 HP | 100 |
| 최대 스태미너 | 100 |
| 최대 브레이크 게이지 | 100 |
| 최대 다운 카운트 | 3 |
| 기본 주사위 | d6(1~6) |

각 캐릭터는 다음 전투 요소를 가진다.

- 기본 행동: 공격, 방어, 회피
- 액티브 스킬 슬롯 5개
- 패시브 스킬 슬롯 1개
- 현재 HP, 스태미너, 브레이크 게이지, 다운 카운트
- 완전 그로기 및 KO 여부
- 상태이상과 예약 효과 목록

모든 자원은 원칙적으로 `0 이상, 현재 최대치 이하`로 제한한다.

## 4. 경기 구성과 승패

### 4.1 목표 지원 구성

- 1 대 1
- 1 대 N
- N 대 N

현재 Python POC는 1 대 1만 구현한다. 1 대 N/N 대 N은 이 문서의 교대 규칙을 따르는 후속 범위다.

한 라운드에는 각 진영에서 활성 캐릭터 한 명만 출전한다. 따라서 실제 판정은 항상 활성 캐릭터 두 명 사이의 1 대 1 판정이다.

### 4.2 승패 조건

- 개인의 다운 카운트가 최대 다운 카운트에 **도달**하면 해당 캐릭터는 KO된다.
- 진영에 속한 모든 캐릭터가 KO되면 해당 진영이 패배한다.
- 같은 판정에서 양측 HP가 모두 0이 되면 더블 다운이다.
- 같은 판정에서 양 진영의 마지막 생존 캐릭터가 모두 KO되면 경기는 무승부다.
- 한쪽 마지막 캐릭터만 KO되면 상대 진영이 승리한다.

### 4.3 경기 길이

- 기본 최대 라운드는 무제한이다.
- 밸런스 목표는 기준 1 대 1 경기가 대체로 5라운드 전후에 끝나는 것이다. 평균을 정확히 40턴에 맞추지는 않는다.
- 자동 시뮬레이션은 오류·교착 탐지를 위해 게임 규칙과 별개의 안전 한도를 가져야 한다. 권장 초기값은 100라운드이며, 도달 시 승패가 아닌 `STALEMATE`로 기록한다.

## 5. 라운드와 출전 순환

### 5.1 라운드 길이

- 한 라운드는 정확히 8턴으로 구성된다.
- 다운으로 소비되는 스킵 턴도 8턴에 포함한다.
- 경기 종료 조건이 충족되면 남은 턴과 관계없이 즉시 경기를 종료한다.

### 5.2 라운드별 교대

- 다인 진영은 매 라운드 종료 후 다음 전투 가능 캐릭터로 교대한다.
- 출전 순서는 진영별 고정 순환 대기열로 관리한다.
- KO된 캐릭터는 대기열에서 제외한다.
- 마지막 순번 다음에는 첫 번째 생존 캐릭터로 돌아간다.
- 한 명뿐인 진영은 같은 캐릭터가 다음 라운드에도 계속 출전한다.
- 일반 다운은 즉시 교대 사유가 아니다.

예시:

```text
Round 1: A
Round 2: B
Round 3: C
Round 4: A
```

### 5.3 인터벌과 교대 순서

라운드 종료 시 다음 순서를 고정한다.

1. 라운드 말 다운 캐릭터의 기상 처리
2. 해당 라운드에 출전했던 캐릭터의 인터벌 회복
3. 완전 그로기 해제
4. 인터벌에 따른 상태이상 남은 턴 감소
5. 양 진영의 다음 생존 캐릭터 선택
6. 다음 라운드 시작

벤치 캐릭터는 HP, 스태미너, 브레이크 게이지를 회복하지 않는다.

## 6. 턴 시행 절차

정상 상태의 양측이 행동 가능한 경우 한 턴은 다음 순서로 처리한다.

1. 턴 시작 효과 처리
2. 행동 가능 여부 및 예약 효과 확인
3. 양측 기본 행동 선택
4. 양측 액티브 스킬 선택 또는 미사용 선택
5. 스킬 사용 가능 여부와 대상 검증
6. 선택 확정 후 양측 동시 공개
7. 스태미너 비용 지불
8. 강제 행동 효과 적용
9. 양측 d6 원본 주사위 굴림
10. 주사위 조작 효과의 우선순위를 판정하고 선택된 범위 적용
11. 최종 주사위의 우열 결정
12. 27개 기본 결과표 조회
13. 액티브·패시브·상태이상 수정치 적용
14. 양측 자원 변화를 임시 결과로 계산
15. HP, 스태미너, 브레이크 게이지 변화를 동시 반영
16. 완전 그로기 진입 판정
17. 다운, KO 및 경기 종료 판정
18. 턴 종료 효과 처리
19. 이전 턴부터 활성화된 상태이상의 남은 턴 감소 및 만료 효과 제거
20. 라운드 턴 카운터 증가

양측 결과는 반드시 동시 반영한다. 먼저 처리된 캐릭터의 다운이나 KO 때문에 같은 턴에 확정된 상대 효과를 취소해서는 안 된다.

## 7. 기본 행동과 27개 결과표

### 7.1 행동

- 공격(Attack)
- 방어(Defend)
- 회피(Evade)

### 7.2 판정 조합

양측 행동 조합 9개와 주사위 우열 3개를 결합하여 총 27개 결과를 사용한다.

주사위 우열은 Player 관점에서 다음 세 가지다.

- Player Win: Player 주사위 > Enemy 주사위
- Draw: Player 주사위 = Enemy 주사위
- Enemy Win: Player 주사위 < Enemy 주사위

각 결과 행은 최소한 다음 값을 표현할 수 있어야 한다.

- Player HP 변화
- Player 스태미너 변화
- Player 브레이크 게이지 변화
- Enemy HP 변화
- Enemy 스태미너 변화
- Enemy 브레이크 게이지 변화
- 부가 효과 또는 상태이상 목록

현재 구현에 사용하는 27개 결과의 실제 수치는 `BASIC_RESULT_TABLE_DRAFT_V0.1.md` 문서 버전 0.4와 `battle_sim.py`의 `RESULT_TABLE`을 기준으로 한다.

## 8. 주사위

- 기본 주사위는 d6이며 원본 결과 범위는 1~6이다.
- 양측은 동일한 턴에 각각 독립적으로 한 번 굴린다.
- CPU는 Player의 선택이나 주사위를 본 뒤 자신의 선택을 바꿀 수 없다.
- 원본 굴림, 모든 보정 과정, 최종값을 전투 로그에 기록한다.
- 동일 난수 시드와 동일 입력은 동일 결과를 생성해야 한다.

여러 주사위 조작 효과가 한 캐릭터에게 동시에 적용되면 각 효과를 `[minimum, maximum]` 범위로 정규화한 뒤 다음 우선순위를 적용한다.

```text
1. minimum이 더 높은 효과
2. minimum이 같으면 maximum이 더 낮은 효과
```

우선순위가 가장 높은 하나의 조작 효과만 최종 주사위 범위에 적용한다. 고정값 효과는 `minimum = maximum`인 범위로 취급한다.

예시:

```text
럭키다이스: [7, 7]
패배의 기운: [1, 3]

7 > 1이므로 럭키다이스가 우선하며 최종 주사위는 7이다.
```

조작 효과는 기본 d6 범위를 벗어난 값을 만들 수 있다. 따라서 최종 주사위를 다시 1~6으로 제한하지 않는다.

두 효과의 minimum과 maximum이 모두 같으면 동일한 제한이므로 충돌로 취급하지 않는다. 두 효과는 함께 존재할 수 있으며 주사위 결과에는 동일한 범위를 한 번 적용한다.

## 9. 액티브 스킬

> 구현 상태: Python Phase A 데이터 모델·검증기, Phase B 전투 입력·비용·쿨다운·횟수 처리, Phase C timing·priority·여섯 즉시 효과 카테고리와 Phase D 상태·예약 적용 방식까지 완료했다.
>
> 확정 데이터 스키마와 Python 구현 TODO의 단일 기준은 `ACTIVE_SKILL_SCHEMA.md`다.

### 9.1 사용 방식

- 캐릭터는 기본 행동을 먼저 선택한다.
- 그다음 액티브 스킬 하나를 선택하거나 사용하지 않는다.
- 기본 행동과 스킬은 함께 동시 공개된다.
- 액티브 스킬은 스태미너를 소비한다.
- 요구 스태미너가 부족한 스킬은 선택할 수 없다.

### 9.2 효과 내용과 적용 방식

효과 내용은 다음 여섯 카테고리로 확정한다.

- `resource_change`: 현재 HP·STA·BRK 직접 변화
- `result_modifier`: 결과표가 산출한 HP·STA·BRK 변화량 수정
- `dice_modifier`: 주사위 minimum·maximum 및 후속 확장 조작
- `action_control`: 기본 행동 허용·금지·강제
- `status_control`: 상태 제거·지속시간·차단·면역 관리
- `skill_control`: 비용·쿨다운·사용 횟수 관리

적용 방식은 효과 내용과 분리하여 `immediate`, `status`, `queued`, 예약된 `passive`로 정의한다. 상태이상 부여는 독립 효과 카테고리가 아니라 효과를 `status` 방식으로 저장하는 것이다. 예약 효과도 독립 효과 내용이 아니라 `queued` 적용 방식이다.

### 9.3 데이터 요구사항

각 액티브 스킬은 최소한 다음 필드를 가진다.

- ID와 표시 이름
- 스태미너 비용
- 대상 규칙
- 허용 기본 행동
- 적용 시점
- 효과 목록
- 지속시간 또는 남은 턴 수
- 중첩 규칙
- 우선순위
- 쿨다운 또는 경기당 사용 제한(사용하는 경우)
- 현재 레벨과 최대 레벨
- 레벨별 비용·효과값 또는 강화 곡선

구현 스키마는 `SkillDefinition → levels[] → applications[] → effects[]` 구조를 사용한다. `requirements.allowed_actions` 및 재귀 조건식은 스킬 사용 가능성을 판정하고, 각 application의 `condition`은 사용 후 개별 효과 발동을 판정한다.

### 9.4 성장과 전력 격차

- 액티브 스킬은 강화 가능한 구조로 정의한다.
- 스킬 레벨이 오르거나 보유 스킬 수가 늘어나면, 스킬 구성이 고정된 기존 상대에 대한 전체 기대 승률이 상승하는 방향을 목표로 한다.
- 큰 스킬 전력 차이에서 우세 측이 압도하거나 열세 측의 승리가 매우 어려운 결과는 허용한다. 스킬 성장은 의도적인 수직 전력 상승 요소다.
- 모든 개별 매치업과 표본에서 승률이 단조 증가할 필요는 없지만, 동일 조건의 충분한 반복 실험에서 전체 정책군 상대 기대 성능이 역행해서는 안 된다.

### 9.5 단일 스킬 영향력 제한

- 단일 스킬 하나가 대부분의 경기 승패를 독점적으로 결정하는 설계는 지양한다.
- 강한 효과는 기본 행동 선택, 자원 비용, 쿨다운, 사용 시점 또는 상대 대응과 결합되어야 한다.
- 비슷한 총 스킬 전력의 구성에서는 특정 스킬을 제거한 비교 실험을 실시하여 한 스킬의 한계 기여도를 확인한다.
- 단일 스킬 추가만으로 광범위한 정책 상대가 일방적으로 무력화되면 비용, 쿨다운, 효과량 또는 대응 가능성을 재조정한다.

## 10. 패시브 스킬

> 구현 상태: 목표 명세만 존재하며 Python POC에는 아직 구현되지 않았다.

- 패시브는 스태미너를 소비하지 않는다.
- 경기 시작 시 또는 정의된 조건이 충족될 때 적용된다.
- 하나의 패시브가 여러 효과를 가질 수 있다.

지원 효과 유형:

- 경기 중 최대 HP, 스태미너 또는 브레이크 게이지를 일정 비율 강화
- 최대 다운 카운트 증가
- 특정 기본 행동의 결과 강화
- 특정 상태이상 면역

패시브 적용으로 최대 자원이 증가할 때 현재 자원도 같이 증가하는지는 아직 확정되지 않았다.

## 11. 브레이크 게이지와 완전 그로기

### 11.1 완전 그로기 진입

- 브레이크 게이지가 최대치에 도달하면 해당 캐릭터는 즉시 완전 그로기에 진입한다.
- 완전 그로기 캐릭터는 행동 및 액티브 스킬을 선택할 수 없다.
- 완전 그로기 캐릭터는 주사위를 굴리지 않는다.
- 완전 그로기는 다운 후 기상하거나 라운드가 종료될 때까지 유지된다.

### 11.2 그로기 대상 행동 판정

행동 가능한 상대는 그로기 대상에게 공격, 방어, 회피 중 하나를 자유롭게 선택하며 필요하면 액티브 스킬도 함께 선택한다.

그로기 대상에는 기존 27개 결과표를 사용하지 않고 다음 전용 결과표를 사용한다.

- 공격 대 그로기
- 방어 대 그로기
- 회피 대 그로기

각 전용 결과는 해당 행동의 `Dice Win` 기준 효과를 1.5배로 강화한 **최종값**으로 데이터에 기록한다. 런타임에서 다시 1.5배를 곱하지 않는다.

POC 전용 수치는 각 행동의 **동일 행동 조합 Dice Win**을 기준으로 한다. 그로기 캐릭터는 행동하지 않으므로 동일 행동 행에 포함된 그로기 캐릭터 자신의 행동 효과는 제외하고, 행동 가능한 캐릭터가 만든 핵심 효과만 1.5배한다.

그로기 상태는 브레이크 게이지가 최대치인 상태이므로 그로기 전용 결과로 대상의 브레이크 게이지를 감소시키지 않는다. 양수 축적값은 데이터에 남길 수 있지만 실제 게이지는 최대치에 고정한다. 라운드 종료 또는 다운 후 기상에 따른 감소는 11.3의 해제 규칙에서만 처리한다.

그로기 대상 판정은 자동 성공이므로 상대 주사위와의 비교는 하지 않는다. 공격자가 액티브 스킬이나 다른 효과 때문에 주사위를 필요로 하는 경우를 대비해, 공격자 단독 d6을 굴릴 수 있는 구조는 유지한다.

그로기 전용 행동의 기본 역할은 다음과 같다.

- 공격: HP 피해 중심
- 방어: 자신의 HP 회복 및 스태미너 회복
- 회피: 카운터 개념의 HP 피해 및 대상 브레이크 게이지 축적

### 11.3 완전 그로기 해제

- 다운 후 기상 시 브레이크 게이지를 최대치의 50%로 설정하고 완전 그로기를 해제한다.
- 라운드 종료 시 완전 그로기를 해제하고 인터벌 규칙에 따라 현재 브레이크 게이지를 절반으로 감소시킨다.
- 최대치에서 라운드가 끝났다면 결과적으로 최대 브레이크 게이지의 50%가 된다.
- 라운드 말 다운으로 기상한 경우에는 기상 시 50% 설정 후 인터벌에서 다시 절반이 되어 최대치의 25%가 된다.

## 12. 다운, 기상 및 KO

### 12.1 다운 판정

- 한 턴의 모든 자원 변화를 동시 반영한 뒤 HP가 0이면 다운된다.
- 다운 시 다운 카운트를 1 증가시킨다.
- 증가한 다운 카운트가 최대 다운 카운트에 도달하면 즉시 KO된다.
- KO 캐릭터는 기상하지 않으며 이후 출전 순환에서 제외된다.

### 12.2 기상 가능 시

아직 최대 다운 카운트에 도달하지 않았다면 다음을 적용한다.

- 필요한 스킵 턴 수 = 현재 다운 카운트
- 스킵 턴은 현재 라운드의 8턴에 포함된다.
- 다운 캐릭터의 상태이상 남은 턴은 스킵 턴에도 정상적으로 감소한다.
- 상대는 스킵 턴마다 자신의 최대 HP의 4%를 회복하며 대기한다.
- 대기 중에는 기본 행동과 액티브 스킬을 선택하지 않고 주사위도 굴리지 않는다.
- 스킵 완료 후 HP를 최대 HP의 50%로 설정한다.
- 완전 그로기를 해제한다.
- 브레이크 게이지를 최대치의 50%로 설정한다.

대기 회복은 매 스킵 턴마다 독립적으로 계산하고, 소수점은 내리며, 최대 HP를 초과할 수 없다.

라운드의 마지막 턴이 다운 대기 턴이어도 최대 HP의 4% 회복을 적용한다. 이후 라운드 인터벌 회복도 정상적으로 중첩한다.

예시:

```text
첫 번째 다운: 1턴 스킵 후 기상
두 번째 다운: 2턴 스킵 후 기상
세 번째 다운: 최대 다운 카운트가 3이면 KO
```

### 12.3 라운드 말 다운

필요한 스킵 턴 수가 현재 라운드의 남은 턴 수 이상이면 남은 턴을 모두 소비하고 인터벌 직전에 기상한 것으로 처리한다.

이후 기상 회복과 인터벌 회복을 중첩 적용한다.

기준 캐릭터가 라운드 말에 기상하는 경우:

```text
기상: HP를 최대치의 50%로 설정
인터벌: 최대 HP의 33% 추가 회복
최종 HP: 최대치의 83%
```

브레이크 게이지는 기상 시 최대치의 50%로 설정된 뒤 인터벌에서 다시 절반으로 감소하므로 최대치의 25%가 된다.

### 12.4 더블 다운

- 양측 HP가 같은 턴에 0이 되면 양측 모두 다운 카운트를 증가시킨다.
- 한쪽만 KO 조건에 도달하면 해당 캐릭터를 제거하고 진영 승패를 판정한다.
- 양측 모두 KO되었지만 양 팀에 생존 벤치 캐릭터가 있다면 라운드를 종료한 뒤 다음 생존 캐릭터끼리 경기한다.
- 양 진영의 마지막 캐릭터가 동시에 KO되면 무승부다.
- 양측 모두 기상 가능하면 각자의 다운 카운트만큼 스킵 턴을 계산한다.
- 먼저 스킵을 마친 캐릭터는 즉시 기상하며, 상대가 기상할 때까지 남은 각 턴마다 자신의 최대 HP의 4%를 회복하며 대기한다.
- 두 캐릭터가 모두 기상한 턴에는 대기 회복까지만 처리하며, 다음 턴부터 양측의 행동 선택을 재개한다.
- 두 캐릭터가 같은 턴에 기상하면 해당 턴에는 추가 대기 회복 없이 다음 턴부터 행동 선택을 재개한다.

## 13. 라운드 인터벌

인터벌 회복은 해당 라운드에 출전한 캐릭터에게만 적용한다.

| 항목 | 처리 |
|---|---|
| HP | 최대 HP의 33%만큼 회복 |
| 스태미너 | 최대 스태미너의 50%만큼 회복 |
| 브레이크 게이지 | 현재 값의 절반으로 감소 |
| 완전 그로기 | 해제 |

- HP와 스태미너는 최대치를 초과하지 않는다.
- 회복량의 기준은 패시브 등 경기 내 수정이 반영된 현재 최대치다.
- 벤치 캐릭터는 자원 회복을 받지 않는다.
- 라운드 말 기상 회복과 인터벌 회복은 중첩된다.

## 14. 상태이상과 예약 효과

> 구현 상태: `StatusEffect` payload 실행, 다음 자기 턴 활성화, refresh·replace, 정화와 `QueuedEffect` trigger·expires·consumes를 Python POC에 구현했다. 행동 불능·지속 피해·면역·다중 중첩은 아직 확장 범위다.

### 14.1 귀속과 지속시간

- 모든 상태이상과 예약 효과는 캐릭터 객체에 귀속된다.
- 캐릭터가 벤치로 이동해도 다른 캐릭터에게 이전되지 않는다.
- 모든 상태이상은 `남은 턴 수`를 가진다.
- 상태이상은 부여된 턴에는 발동하지 않고 남은 턴 수도 감소하지 않는다.
- 상태이상은 부여된 다음 턴부터 발동하고, 해당 턴 종료 시 남은 턴 수가 1 감소한다.
- 출전 중에는 행동 판정 턴과 다운 스킵 턴 모두 남은 턴 수가 감소한다.
- 상태이상 때문에 행동이 완전히 제한된 턴에도 남은 턴 수는 감소한다.
- 출전 캐릭터는 라운드 인터벌에서 남은 턴 수가 추가로 2 감소한다.
- 벤치에서 라운드 하나를 보낸 캐릭터도 라운드 종료 시 남은 턴 수가 2 감소한다.
- 감소 후 남은 턴 수가 0 이하이면 상태이상을 제거한다.

예를 들어 1라운드 3턴에 3턴짜리 혼란이 부여되면 4·5·6턴에 발동하고 각 턴 종료 시 감소하여 7턴부터 해제된다. 8턴에 부여된 상태이상은 해당 턴 감소를 받지 않고 인터벌 감소 2만 적용받는다.

- 상태이상 면역 캐릭터에게는 해당 상태이상이 처음부터 부여되지 않는다.
- 액티브 스킬로 상태이상을 중간에 즉시 해제할 수 있다.

상태이상과 해제의 턴 처리 원칙은 다음과 같다.

1. 턴 시작 시, 이전 턴부터 보유한 활성 상태이상의 효과를 적용한다.
2. 행동이 가능하면 기본 행동과 액티브 스킬을 선택한다.
3. 상태이상 해제 스킬은 스킬이 실행되는 시점에 이미 보유 중인 상태이상만 해제한다.
4. 같은 턴의 동시 판정으로 새로 부여되는 상태이상은 그 턴에 먼저 선택한 해제 스킬로 해제할 수 없다.
5. 새 상태이상은 다음 턴부터 활성화된다.
6. 턴 종료 시 해당 턴에 활성화되어 있던 상태이상의 남은 턴 수를 1 감소시킨다.

따라서 활성 상태이상 X가 이미 적용되는 턴에 해제 스킬을 사용하면 그 턴의 X 효과는 먼저 발생하지만, 해제 이후의 다음 턴부터는 X가 발생하지 않는다. 반대로 X가 새로 부여되는 턴에 미리 사용한 해제 스킬은 X를 제거하지 못한다.

### 14.2 상태이상 데이터 요구사항

각 상태이상은 최소한 다음 필드를 가진다.

- ID와 표시 이름
- 남은 턴 수
- 적용 시점
- 효과 목록
- 중첩 가능 여부와 최대 중첩
- 재적용 시 갱신 방식
- 해제 가능 여부
- 면역 태그
- 출전 중/벤치 중 지속 여부

### 14.3 상태이상 적용 순서

권장 기본 순서는 다음과 같다.

```text
면역 확인
→ 기존 동일 효과 확인
→ 중첩 또는 지속시간 갱신
→ 상태 부여
→ 즉시 효과 실행
```

확정 상태이상이라도 면역을 무시한다는 별도 문구가 없다면 면역이 우선한다.

## 15. 자원과 수치 계산 원칙

- HP, 스태미너, 브레이크 게이지는 0 미만 또는 최대치 초과가 될 수 없다.
- 액티브 스킬 비용은 선택 검증 후 효과 적용 전에 지불한다.
- 효과가 무효화되거나 면역에 막혔을 때 비용을 반환할지는 아직 확정되지 않았다.
- 배율 계산은 원본 값에 모든 고정 수정치를 더한 뒤 배율을 적용하는 방식을 권장한다.
- 모든 계산 결과의 소수점은 계산 단계의 최종값에서 내림 처리한다.

권장 계산 형태:

```text
최종 수치 = Floor((기본값 + 고정 수정치 합) × 배율 수정치 곱)
```

## 16. CPU 행동

- CPU도 Player와 동일한 실행 규칙 안에서 기본 행동과 액티브 스킬을 선택한다. 쉬움 3종의 예정형 스킬 선택과 랜덤 Player를 구현했으며, 기존 엔진 호출은 기본값으로 스킬 자동 선택을 끈다.
- CPU 선택은 Player 선택 공개 전에 확정한다.
- 2026-09-03 롤백한 가중치·효용·학습 선택기는 재사용하지 않는다. 새 쉬움 적 선택기는 기본 행동을 먼저 확정하고 예정된 스킬만 검사한다. 일정·실패·이월 규칙은 `EASY_ENEMY_SKILLS.md`를 따른다.
- 같은 난수 시드와 동일 상태에서는 같은 선택을 재현할 수 있어야 한다.

CPU 판단에 사용할 수 있는 요소:

- 자신의 HP, 스태미너 및 브레이크 게이지
- 상대의 HP, 스태미너 및 브레이크 게이지
- 양측 상태이상
- 직전 행동 기록
- 사용 가능한 액티브 스킬
- 상대의 완전 그로기 여부

현재 Python POC는 양측에 독립 전략을 주입하고, 정책 난수와 전투 주사위 난수를 분리한다. CPU는 같은 턴의 상대 선택을 읽을 수 없으며 과거에 공개된 행동·주사위와 현재 공개 상태만 사용한다. 비율형, 상태 임계값형, 최근 행동 적응형, 기대값형, 후회 최소화형 정책이 구현되어 있다. 구체적인 정책 ID와 실험 결과는 `BATTLE_SIM_POC_PROGRESS.md`를 참조한다.

## 17. 확정 사항과 남은 결정 사항

### 17.1 현재 확정 및 구현된 사항

- 공격·방어·회피의 순환 상성: `공격 > 회피 > 방어 > 공격`
- 27개 기본 결과와 그로기 전용 3개 결과
- 결과표에 포함된 스태미너 변화 외에 별도의 기본 행동 비용은 없음
- 다운 대기 회복은 최대 HP의 4%
- 8턴 라운드, 인터벌 회복, 라운드 말 기상 중첩
- 완전 그로기, 다운, KO 및 100라운드 안전 한도
- CPU 블라인드 동시 선택 및 시드 재현

### 17.2 스킬 및 확장 구현 전에 결정할 항목

1. 액티브 스킬별 비용, 쿨다운 및 경기당 사용 제한
2. 행동 강제 효과가 여러 개일 때 우선순위
3. 면역에 막히거나 실행 불가능해진 스킬의 비용 반환 여부
4. 패시브가 최대 자원을 높일 때 현재 자원 증가 방식
5. 상태이상 재적용 및 중첩 규칙
6. 스킬 효과 배율과 고정 수정치의 중첩 상한
7. 보통 이상 적의 스킬 자동 선택 요구사항과 결정 방식 (쉬움 3종은 구현)

## 19. 전투 로그 요구사항

각 턴마다 최소한 다음을 기록한다.

- 경기 난수 시드
- 라운드와 턴 번호
- 활성 캐릭터
- 양측의 기본 행동과 액티브 스킬
- 원본 주사위
- 적용된 모든 주사위 보정과 최종 주사위
- 조회한 결과표 행 ID
- 각 효과의 적용 전후 수치
- 상태이상 부여, 감소, 해제
- 완전 그로기 진입 및 해제
- 다운, 기상, KO 및 교대
- 승패 또는 교착 결과

로그는 사람이 읽는 메시지와 재현용 구조화 데이터를 분리하는 것이 좋다.

## 20. POC 검증 기준

최종 엔진은 최소한 다음 사례를 자동 테스트해야 한다.

1. 27개 행동·주사위 조합의 올바른 결과표 조회
2. 양측 자원 변화의 동시 적용
3. 브레이크 100 도달 시 완전 그로기 진입
4. 그로기 전용 결과표 자동 성공 처리
5. 다운 카운트별 1턴·2턴 스킵과 3번째 다운 KO
6. 다운 상대를 기다리는 동안 턴당 최대 HP 4% 회복
7. 더블 다운 후 먼저 기상한 캐릭터의 대기 회복
8. 라운드 말 기상 후 HP 83%, 브레이크 25% 처리
9. 더블 다운과 양측 KO
10. 라운드 종료 시 출전 캐릭터만 자원 회복
11. 벤치 캐릭터 자원 미회복 및 상태이상 `-2`
12. 상태이상의 부여 다음 턴 발동, 매 턴 감소 및 인터벌 추가 `-2`
13. 다운 스킵 중 상태이상 감소
14. 행동 불능 상태이상 중 지속시간 감소
15. 새 상태이상을 같은 턴의 선행 해제 스킬로 제거할 수 없음
16. 주사위 조작의 minimum 우선 및 maximum 보조 우선순위
17. 동일 범위 주사위 조작 효과의 비충돌 처리
18. 모든 최종 계산값의 소수점 내림
19. KO 캐릭터를 제외한 라운드별 순환 교대
20. 동일 시드와 동일 입력의 완전 재현
21. 100라운드 안전 한도에서 `STALEMATE` 기록

현재 자동 테스트는 기존 86개와 쉬움 적 스킬·선택기 검증 20개를 합쳐 총 106개다. Phase D 완료 당시 100,000경기 무스킬 기준선은 Player 49.419%, Enemy 50.032%, 더블 KO 0.549%, 평균 34.4389턴으로 기존 수치와 일치했다. 새 쉬움 적 동일 장착 스킬 대전은 별도로 총 3,000경기를 실행했으며 `EASY_ENEMY_PLAYTEST_RESULTS.md`에 기록한다. 위 목록 전체가 완료된 것은 아니며 다음 항목은 확장 구현과 함께 보강해야 한다.

- 다인 교대와 벤치 캐릭터 처리
- 실제 행동 불능·면역·중첩 상태이상
- 패시브 적용 방식과 면역·다중 중첩 상태
- 여러 스킬의 고정 수정치·배율·소수점 내림 복합 사례
- 스킬 사용 CPU와 동일 시드 재현
